# Astra model orchestration

## 1. Purpose

This file allocates Astra Ultra and Astra Max by epistemic role. Model names do not confer mathematical status; independence comes from isolated inputs and fresh reconstruction.

## 2. Root coordinator: Astra Ultra

Use one Ultra root session as campaign director. Its responsibilities are:

- freeze the exact round target and negation;
- allocate genuinely distinct routes;
- resolve normalization and state conflicts;
- compare outputs from Max workers;
- perform the hardest cross-route synthesis;
- decide when a claim is mature enough for isolated audit;
- protect source-of-truth ledgers;
- enforce retractions and scope limits;
- create durable checkpoints.

The root Ultra session must not certify its own proof. It may self-check and prepare an audit dossier only.

## 3. Default workers: Astra Max

Use Max for most sustained work:

- exact generator derivations;
- U-statistic and cumulant combinatorics;
- pair/multi-particle backward equations;
- singular estimates and regularization;
- source theorem extraction;
- one-dimensional/Boursier analysis;
- counterexample construction;
- symbolic and numerical experiments;
- TeX drafting and repository integration on route branches.

A Max worker receives a bounded task card, not the entire campaign narrative unless needed.

## 4. Ultra escalation

Escalate a bounded task to a fresh Ultra session when:

- two Max routes disagree on a load-bearing coefficient;
- critical power counting does not decide finite versus infinite closure;
- a new renormalized limiting object must be designed;
- a singular estimate has resisted at least two distinct Max mechanisms;
- a route appears to prove an unexpectedly strong theorem;
- an obstruction would materially change the mission;
- the coordinator needs an isolated high-depth reconstruction.

Do not spend Ultra cycles on routine file edits, bibliography cleanup, or computations that Max can execute and verify.

## 5. Recommended active lanes

Keep at most eight concurrent lanes unless the root coordinator documents why more are nonredundant:

1. exact finite-\(N\) algebra and k-body recursion — Max;
2. pair/multi-particle Poisson corrector — Max;
3. BBGKY/cumulant independent derivation — Max;
4. singular renormalization and ultraviolet classification — Max;
5. local Gibbs/static response — Max;
6. one-dimensional ordered route — Max;
7. falsification/counterexample route — Max, isolated from construction;
8. source/normalization audit — Max.

Ultra integrates and intervenes at gates.

## 6. Parallelism

Parallelize:

- source reading;
- independent derivations;
- counterexample searches;
- separate solvable models;
- discovery code versus verifier code;
- bounded theorem-to-source audits.

Serialize:

- edits to `STATE/` canonical ledgers;
- edits to the cumulative memorandum;
- changes to frozen theorem statements;
- final coefficient tables;
- package creation and release.

Use one worktree per writable route. Never let two agents edit the same canonical file concurrently.

## 7. Audit isolation

### Self-check

The constructor or root Ultra rereads the proof. Status remains `SELF_CHECKED` at most.

### Isolated reconstruction

Launch a fresh Max or Ultra session with only:

- frozen claim;
- definitions and normalization;
- permitted source inputs;
- expected output template;
- repository hash.

Withhold the candidate derivation until reconstruction is complete. Then compare line by line.

### Hostile review

A fresh agent receives the proof and is instructed not to repair it. It recomputes load-bearing steps and issues a verdict.

One uninterrupted context cannot be made independent by changing role labels.

## 8. Configuration

The repository includes `.codex/config.toml.example` for safe concurrency settings only. Model and reasoning-level syntax can change with Codex releases, so select Astra Ultra/Max through the current Codex interface or verified local configuration. Do not guess model slugs or unsupported configuration keys.

Before launch, confirm:

- Codex CLI is at least `0.153.0` when using CLI;
- the desktop app is current when using desktop Codex;
- Astra is available under the account/workspace;
- subagents are enabled;
- the root coordinator and worker model selections are recorded in `STATE/ENVIRONMENT.md`.
